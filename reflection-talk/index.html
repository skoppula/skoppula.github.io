Building a model

Slot 0 is the original trackerEverything new is added on top, so ordinary tracking cannot get worse at the start.
Slots talk to each otherOtherwise several slots collapse onto the same high-contrast surface.
Each slot says if its surface existsMost rays cross fewer than 8 surfaces, so unused slots must switch themselves off.

A new task needs new metrics: one headline, two that say why

Existence-aware AJ

The headline. Scores 1 only if every surface is found, none invented, and each is followed while hidden.

Detection AP

Did it find the surfaces, and rank real ones above invented ones?

Localization δavg

For the surfaces it tracks, how close is it?

The split is a debugging tool

A model that does nothing: copy the visible track into all 8 slots.

“how close?” on hidden surfaces.588
“did it find them?”.006

A hidden surface sits on the same pixel as the visible one at the query and often stays a few pixels away, so a copy counts as “close”. Detection only scores frames where the two have separated: it found nothing.

So: can synthetic environments help supply training data and the eval?

Q1Can we generate it?

Yes. 14,916 dynamic scenes and 39.7M labelled rays, with no human labels. 99.4% of scenes pass the render checks (4,968 of 5,000 in one collection).

Q2Can we trust it?

With checks at every stage. Scenes, renders and splits pass automated gates, and a do-nothing baseline shows why no metric is trusted on its own.

Q3Does it work?

Yes, on what we can measure. Hidden-surface detection from 0 to .577, first-surface tracking on real video intact. Not yet shown: hidden surfaces on real video, where no labels exist.

What I would do differently
Degenerate baselines firstcopy, static, "front of the same object", before any model.
Intervals from day onepaired bootstrap over scenes; seed spread for every design claim.
A small real test setmulti-camera rigs can label some hidden surfaces: what one view hides, another sees.

Food for thought in designing our benchmarks

How do we design scoring rubrics and verifiers for hidden trajectories that have no visual grounding? Plausible outputs should not be penalized even if they are not GT!

Baselines cost ~10,000 GPU-hours here. What is the smallest eval that preserves the ranking, and how do you verify that it does?

When LLMs write the environments, when does the generator's taste become the thing models overfit to?

Headline metric design: World 3D Average Jaccard

One score, every query, every view, in one world frame. It only goes up if all five parts are right, and each part has its own debugging metric.
